Vibe Kanban keeps you organised while running multiple coding agents in parallel by streamlining how you plan and review their work.

## 1. Launch Vibe Kanban

Start the Vibe Kanban client and open the UI in your browser:


```bash
npx vibe-kanban
```

## 2. Confirm your preferences

The first time you run Vibe Kanban, you'll be asked to set your preferred:

- Coding agent
- IDE
- Notification preferences

<Info>
These preferences can be changed at any time from the settings dialog
</Info>

  <img src="/images/onboarding-basic-setup.png" alt="Placeholder image for preferences setup: coding agent, IDE, and sound notifications." />
</Frame>

## 3. Create a workspace

**Workspaces** are the core concept of Vibe Kanban. A workspace is a space to work on a task with a coding agent. When you create a workspace, Vibe Kanban automatically creates git worktrees for your selected repositories, and launches your coding agent.

After you confirm your preferences, Vibe Kanban opens the create workspace view. No account or sign-in is needed.

<Frame>
  <img style={{maxHeight: "400px"}} src="/images/workspaces-create-new.png" alt="Create workspace view showing project selection, repository list, and task input" />
</Frame>

To create a workspace:

1. Select the repositories you'd like to work on, and the branch of each repository to base the git worktrees on
2. Choose your coding agent configuration (e.g. model, effort level, plan mode)
3. Describe the task. This becomes the prompt your coding agent receives.

Upon creation, the coding agent immediately begins executing with the given prompt. See [Creating Workspaces](/workspaces/creating-workspaces) for every option.

<Info>
  You can run several workspaces at once, which lets you run multiple coding agents in parallel.
</Info>

## 4. Review a workspace

When the agent finishes, review its changes in the workspace. You can view code changes, leave inline comments for the agent, or preview changes to websites in the built-in browser.

- [Reviewing Code](/reviewing-code) covers the changes panel and the review-feedback loop
- [Browser Testing](/browser-testing) covers previewing your app

## 5. Merge a workspace

When you're ready to merge the changes in a workspace, you can either open a GitHub pull request or merge the workspace branch locally.

<Frame>
  <img src="/images/onboarding-workspaces-merge.png" alt="Workspaces merge" />
</Frame>

## Plan work with issues and a team (optional)

Issues, the kanban board, organisations and [remote access](/remote-access) need a self-hosted Vibe Kanban Cloud server. If you run one, start Vibe Kanban with `VK_SHARED_API_BASE` set to its URL and sign in. See the [self-hosting overview](/self-hosting/overview) and [Issue Management](/issue-management).
